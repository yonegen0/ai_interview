## P2：永続化・AWS実装前の必須決定事項

| 決定事項 | 目的 | 完了条件・必要な成果 |
|---|---|---|
| 非同期起動方式 | 202受付後に処理を継続する | 起動元・実行先・イベント形式を設計し、選定理由を記録 |
| 受付と起動の整合性 | 永続化後の起動漏れを防ぎ回復する | 保存後の起動失敗・起動漏れを検出して回復する手順を定義 |
| 重複実行制御 | 二重評価・二重保存・二重集計を防ぐ | 条件付き更新・ロック・結果確定のルールと競合テストを定義 |
| 期限と再実行 | 処理中のまま滞留させない | 処理期限・ロック期限・失敗分類・再実行条件を確定 |
| 外部AI呼出の応答消失 | 二重課金リスクを制御する | 完了不明時の再実行判断と許容リスクを明記 |
| DynamoDB物理設計 | 6 Routeを本人認可付きで実現する | キー・GSI・Transaction・保持期間・アクセスパターン表を確定 |
| Lambda責務とIAM | 起動経路に対応した最小権限にする | 各Route担当・実行先・起動権限を確定 |
| 運用監視 | 起動漏れ・処理滞留・失敗を検出する | 検出方法・アラーム・回復手順・検証Scenarioを定義 |
| データ保持・削除 | 個人回答と冪等記録の保管を制御する | 回答・評価・Session・冪等記録の保持表、削除処理、復元要件 |
| 利用・費用上限 | 個人・全体の過剰利用を防ぐ | ユーザー別／全体上限、超過応答、境界テスト。有料AIテスト前に設定 |

## 認証・実API接続前の必須事項

- CognitoログインとAccess Token付与・更新を実装し、期限切れ時の導線を検証する。
- ログアウト・ユーザー切替時のQuery Cacheと下書き・未確定要求の分離／破棄を定義する。
- 本人認可・ADMIN再認可、CORSのAuthorization／Content-Type／Idempotency-Keyを検証する。
- モデル・WIF・SDK・Runtime・Provider互換性を公式仕様で確認する。
- 実Backendで練習・同一キー再確認・再読み込み復旧をE2E検証する。
- 接続準備完了は実API接続完了ではない。
