# 全体基本設計書

> 文書バージョン: 2.1\
> 更新日: 2026-09-11  
> 対象フェーズ: Backend実装・Terraform構築・実API接続  
> 情報源方針: 実装時は最新の公式ドキュメントを最優先で再確認する。


## 1. 全体構成
```text
User
 ├─ CloudFront → CloudFront Function → Private S3 → Next.js Static App
 └─ Cognito Email OTP
        ↓ Access Token
    API Gateway HTTP API
      ├─ practice-api → DynamoDB
      ├─ evaluation-api → DynamoDB + OpenAI
      └─ admin-api → DynamoDB + Cognito Admin API
```

## 2. 認証・認可
- Cognito User Pool
- Email OTP
- Self sign-up OFF
- App Client Secretなし
- USER / ADMIN Group
- API Gateway JWT AuthorizerでToken検証
- USER対象はJWT `sub`で決定
- ADMINは`admin-api`でも`cognito:groups`を再検証

## 3. AI
- Responses API
- Stateless
- Structured Outputs
- Pydantic Validation
- `store=false`
- Toolsなし
- Provider差し替え境界を用意
- Production認証はAWS WIF第一候補

## 4. Data
- DynamoDB 1 Table
- On-Demand
- UserProfile／Session／Attempt／Evaluation／冪等要求記録の論理モデル（物理Item分割は未確定）
- 全POSTのIdempotency-Keyで要求再送を識別。各リソースIDはBackend生成
- Profileに管理画面向け集計値を非正規化

## 5. Infrastructure
- Terraform管理
- dev/prod共通module
- stateは専用S3
- `use_lockfile=true`
- bootstrap分離

## 6. 現Frontendとの接続契約

[ADR-002](../../docs/ADR-002-frontend-contract-alignment.md)と[API契約](../../docs/FRONTEND_API_CONTRACT.md)を採用する。
回答受付を永続化して202を返し、FrontendがGETで評価状態とFeedbackを取得する。
100点score、summary、指摘配列、任意回答例を使う。非同期起動方式は次工程で確定する。
現在は認証なしMSW単体MVPであり、図のAWS／認証／実AIは将来構成。
