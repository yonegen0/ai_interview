# 画面遷移・UI詳細設計

> 文書バージョン: 2.1\
> 更新日: 2026-09-11  
> 対象フェーズ: Backend実装・Terraform構築・実API接続  
> 情報源方針: 実装時は最新の公式ドキュメントを最優先で再確認する。

## 1. 中心フロー・静的URL

練習開始 → カテゴリ選択 → 質問表示 → 回答入力 → 評価待機 → 結果 → 再挑戦／次問。

| URL | 責務 |
|---|---|
| / | 入口 |
| /practice/ | カテゴリ選択・Session作成 |
| /practice/session/?sessionId=UUID | 回答・評価待機 |
| /result/?attemptId=UUID | Feedback |

再挑戦は回答画面のmode=retryとfromAttemptIdを使用する。
古い結果では現在の練習へ戻る導線を示し、次問・再挑戦で現在の質問を巻き戻さない。
操作可否は現在のSessionとAttemptで判断する。

## 2. 入力・操作段階

回答は空白のみ禁止、JavaScript文字列長で1〜2000。100〜300文字は推奨。
Frontendは送信単位のIdempotency-Keyを生成し、evaluationIdはBackendが生成する。
操作段階は既存Reducerのanswering／submitting／recovery_required／processing／completed／failedを維持する。
連打を防ぎ、未確定送信中は回答欄を無効化して同じ要求の手動確認へ案内する。

## 3. UI

- Smartphone first。通常回答中はマスコットカードを表示しない。
- 送信中はthinkingカードと無効な送信ボタンを1つ表示し、回答欄を同じDOMで維持する。
- 評価待機はthinkingカード、単一role=status／aria-live=polite。停止・通信エラー時に結果を再確認する。
- 評価失敗はerrorマスコットとattention配色。同じ質問に再挑戦すると空の回答欄へ戻る。
- Feedbackはsuccessのfeaturedカード。総合評価のscoreとsummaryを各1回表示し、質問・回答・良かった点・改善点・任意回答例を続ける。
- 有効な結果のみ「次の練習へ」カードに再挑戦・次問を表示する。取得中・次問準備中・古い結果では表示しない。
- ErrorViewはerror配色、実際のメッセージだけrole=alert。公開Propsとリンク先を維持する。

共通MascotCoachCardはモバイルで見出しと画像を横並び、本文と操作を全幅に配置。
768px以上では本文・操作を左、画像を右に配置する。standardは96／144px、featuredは112／176px。
画像は装飾として読み上げ対象外。画像失敗時も領域・本文・操作を維持する。
画像WebPの512px想定と現実体の不一致は既知事項で、今回は再生成しない。

## 4. 復旧・評価待機

保存済み未確定要求は古いactiveAttemptより優先し、同じキー・本文で手動確認する。
古いcompleted／processing Attemptで新しい要求を削除せず、failed後の再入力下書きも復元する。
質問・再挑戦コンテキストが一致する保存データだけ復元する。
保存不可なら画面内操作を続け、再読み込み復元不可を案内する。タブを閉じた後は保証しない。

評価GETは2秒間隔、30秒で案内、120秒で自動確認停止。
非表示・オフライン・通信エラー・終端・画面離脱で自動取得を停止する。
完了・失敗・アンマウント時にタイマーを止め、新しい評価IDで経過時間を0にして再開する。
Frontendの確認停止は評価失敗・キャンセルではない。

## 5. Accessibility

回答・評価はテキスト描画。375／768／1280pxのはみ出し、操作重複、画像失敗、
キーボード・Focus、Form Label、alert／statusの重複をStorybook・Vitest・E2Eで確認する。
