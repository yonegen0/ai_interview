## 1. この設計書体系の位置づけ

Frontend主要フローとE2Eがほぼ完成している状態から、
Backend実装・Terraform構築・実API接続へ進むための設計書体系。

v2.1では現Frontend契約へ整合し、次の全体方針を採用する。実装済みはMSW単体MVPで、AWS・認証・実AIは次工程。

- Private S3 + CloudFront OAC
- CloudFront FunctionsによるStatic Export URL Rewrite
- Cognito Email OTP Passwordless認証
- USER / ADMIN Cognito Group
- API Gateway HTTP API + JWT Authorizer + CORS
- admin-apiでのADMIN再認可
- Lambda 3分割
- OpenAI Responses API + Structured Outputs
- `store=false`
- OpenAI Tools不使用
- GPT-5.6 Luna / Terraの実データ比較
- Production OpenAI認証はAWS Workload Identity Federationを第一候補
- 全POSTのIdempotency-Key（Frontend生成）、リソースIDはBackend生成
- Session／Attempt／Evaluationの6 Route、202受付とGET、100点評価
- DynamoDB 1テーブル + Profile非正規化
- Terraform S3 backend + `use_lockfile=true`
- Terraform bootstrap分離
- CloudFront用ACMのus-east-1 Provider Alias
- Monitoring / Logging / Model Evaluation設計の追加

## 4. 旧構成からの主な変更

- Secrets Manager前提から、ProductionではOpenAI WIF第一候補へ変更
- CloudFront Function設計書をS3/CloudFront詳細設計へ統合
- CORSをAPI Gateway詳細設計へ追加
- ADMIN判定をJWT Authorizer任せにせずBackend認可へ追加
- Evaluationの識別と要求の冪等性を分離。全POSTをユーザー単位のIdempotency-Keyで識別
- DynamoDB Profileに集計値を非正規化
- Terraform state用bootstrapを追加
- AI Model Evaluationを独立したテスト設計として追加
